# Documentation

## Rules

- The deployment is private: there is no public documentation site, agent corpus, or SEO output (refactor 1c-3). Do not add public pages; `public/robots.txt` disallows all crawling.
- `docs/` holds `docs/engineering/` and `docs/api/`. `docs/api/` is generated by `make generate`. Change the proto instead.
- Source attribution (`docs/engineering/architecture/source-attribution.md`), catalogs, and locales are derived files. Change the generator input, then run `npm run generate`. Never hand-edit the output.
- `CLAUDE.md` is the canonical agent guide. `.claude/rules/` files stay short and link to `CLAUDE.md`, CONTRIBUTING.md, or `docs/engineering/`. Do not copy rules between them. Do not add guide files for other agent tools (`AGENTS.md`, `.cursor/`, `.windsurf/`).
- Engineering records live in `docs/engineering/` ([map](../../docs/engineering/README.md)). Record a solved problem with `/learn` as a lesson in `docs/engineering/solutions/<category>/`, following [its schema](../../docs/engineering/solutions/README.md). Title it with the lesson, not the symptom. Plans need a `status` ([schema](../../docs/engineering/plans/README.md)).
- `docs/engineering/solutions/INDEX.md` and `docs/engineering/plans/INDEX.md` are generated by `npm run generate`. Never hand-edit them.

## Verify

```bash
npm run lint:md
npm run generate:check
node --test tests/engineering-docs.test.mjs              # after changing docs/engineering/
npm run docs:check                                       # after changing the /api/health examples or the CI/CD table
git diff --check
```
